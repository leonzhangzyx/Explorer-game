# 单英雄领地冒险 MVP 实施蓝图

## 技术基线

- Godot 4.7.2 Standard
- GDScript
- 2D 世界地图和 10 × 8 方格战场
- Windows PC 首发
- 1920 × 1080 设计分辨率并支持缩放
- Compatibility 渲染器，优先覆盖普通桌面设备

## 模块边界

| 模块 | 职责 | 不应承担 |
| --- | --- | --- |
| core | 游戏状态、ID、随机流、存档和信号 | 具体 UI 和动画 |
| content | 静态定义、注册表和内容验证 | 修改运行时状态 |
| world | 地图、行动点、迷雾、日期和节点交互 | 战斗规则 |
| battle | 网格、单位行动、技能、AI 和战斗结算 | 世界日期推进 |
| economy | 资源、领地、生产、升级和补给 | 直接绘制界面 |
| recruitment | 外交、震撼、归顺和忠诚 | 战斗表现动画 |
| events | 事件图、条件、选择、任务和标记 | 硬编码具体页面 |
| ui | 状态展示、输入和导航 | 决定规则结果 |
| tests | 单元、集成、内容验证和冒烟流程 | 正式游戏功能 |

## 核心实体

- GameState：当前日期、资源、威胁、任务、随机种子和顶层模式。
- HeroState：英雄属性、等级、技能、装备、伤势和位置。
- ArmyState：英雄引用、编队、容量、士气和补给。
- UnitStackState：兵种 ID、数量、当前个体生命、状态和忠诚。
- TerritoryState：归属、等级、设施、产出、招募池和驻军。
- EncounterState：参与方、外交条件、战斗配置和结算状态。
- EventState：事件节点、已选分支、标记和奖励状态。
- BattleState：网格、单位实例、行动序列、目标和日志。

静态内容定义与运行时状态分离。静态内容使用稳定字符串 ID；运行时实例另有 instance_id。

## 状态流

```text
启动 → 主菜单 → 新游戏或读档 → 世界地图
世界地图 → 遭遇准备 → 外交或战斗
战斗 → 战后结算 → 世界地图
世界地图 → 事件 → 世界地图
世界地图 → 最终首领 → 胜利结算
```

任一时刻只有当前顶层状态接收玩法输入。动画和界面切换不推进规则时间。

## 通信方式

- 模块内部优先直接调用明确接口。
- 跨模块使用带类型参数的信号或应用服务。
- UI 发送意图并订阅状态变化，不直接修改领域对象。
- 战斗返回结算对象，由世界系统应用一次；结算必须具有唯一 ID，防止重复领取。

## 随机数

- 新游戏保存 master seed。
- 派生 world、event、battle、loot 四个随机流。
- 存档保存各随机流状态。
- 相同版本、种子和输入必须得到相同规则结果。

## 存档

- 保存 schema_version、game_version、content_version、seed 和运行时状态。
- 使用稳定 ID，不保存节点路径或对象地址。
- 自动存档先写临时文件，验证成功后替换目标。
- 版本不兼容时显示明确错误；迁移必须显式登记。

## 测试

- 规则单元测试不加载画面。
- 系统集成测试覆盖一天结算、完整战斗、事件链和读档恢复。
- 内容验证检查 ID、引用、数值和事件出口。
- 冒烟测试持续覆盖启动、移动、战斗、占领、招募、保存和读取。

## 调试入口

开发构建将提供指定种子、资源、等级、兵种、传送、事件、战斗、AI 评分、日志导出和内容验证。正式构建不显示调试入口。

# 项目约定

## 命名

- 文件和目录使用 snake_case 英文名。
- 类名使用 PascalCase，函数和变量使用 snake_case，常量使用 UPPER_SNAKE_CASE。
- 内容 ID 使用小写点分命名，例如 `unit.militia`、`skill.heroic_charge`。
- 运行时实例 ID 不得代替内容 ID 写入静态数据。

## 数据

- 规则数值来自 Resource 或 JSON 数据。
- 所有外部引用必须经过内容注册表解析。
- 未知 ID、重复 ID 和非法数值必须在加载时报告。
- 缺失内容不得静默替换成默认单位或空奖励。

## 错误和日志

- 玩家可恢复的问题显示可理解提示。
- 内容错误和不变量破坏使用明确错误日志。
- 日志不记录敏感个人信息。
- 规则结算日志应包含结算 ID，便于排查重复应用。

## 代码边界

- UI 不直接改变 GameState。
- 动画完成信号不决定规则是否执行。
- 系统不得依赖场景树中的任意节点查找其他系统。
- 公开接口使用类型标注。

## 完成定义

功能只有在项目可启动、正常流程可到达、自动测试通过、数据可配置、失败有日志、既有验收未破坏且交付报告完整时才算完成。
